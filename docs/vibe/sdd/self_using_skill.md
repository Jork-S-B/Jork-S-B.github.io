skill内部流程

1. 文章转口播稿
2. 口播稿转开发大纲
3. 每步视觉演示

1. 划定边界
2. 设检查点
3. 自检
4. 修复

#### 该skill中的harness应用

[Harness Engineering](https://www.runoob.com/ai-agent/harness-engineering.html)

目标: 把模型能力/工具能力/人的判断，组织成一条稳定可控的生产流程。

1. 上下文管理: 模型到底看到了什么

    类似skill的按需读取策略(渐进式披露)，运行到某个阶段读对应的、最需要的文档信息，避免被无关内容干扰。

2. 工具系统: 模型到底能做什么

    本skill中主要是读写，但多agent并行开发需要考虑冲突问题。

    - 隔离机制: 1.按章节独立文件夹、CSS前缀；2.全局变量兜底，控制主题、风格、间距

3. 执行与编排: 模型下一步该做什么

    分步执行: 由预设的任务作为起点，步骤 + 人工检查节点组合。

    人工检查节点包括: 初稿审批、素材选择、后续并行开发还是mvp版本(mvp版本为后续的开发提供基准参考)、分支选择等。

4. 状态与记忆: 系统如何跨步骤保持连续性

    持久化开发大纲，将检查点关键决策文档记录，作为开发持续记忆，避免上下文信息不对称。
    
    本skill额外的特色设计: `script.md`把握叙事节奏、`article.md`把握信息密度。

5. 评估与观测: 系统怎么知道自己做得对不对

    如何避免agent自评失真？

    - 自检、修复、汇报: 1.Agent Teams, 由独立的Reviewer Agent审查，但该模式token花费高；2.SubAgent, 由子代理审查，评估效果次之。

6. 约束与恢复: 出错了怎么办，怎么避免跑偏

    节奏不对、ai味太浓这类问题如何处理？如何从某个步骤重做而非全部推倒？

    - 最小切片原则: 定位反馈修复的点在哪一层，只改最小切片。

??? note "Agent Teams & SubAgent"

    - SubAgent, 主Agent任务分发，子Agent执行任务将结果传回，各子Agent之间不干扰（也不讨论），适合结果导向型任务。
    - Agent Teams, 组长+组员，每个组员都是独立会话（token花费高），共享任务列表，适合需要交互反馈的任务。

## motion-showreel

https://github.com/ConardLi/garden-skills/blob/main/README.zh-CN.md#motion-showreel

代码渲染的短视频，讲解视频: https://b23.tv/glJ49SV

### 原理

- 网页（HTML+CSS）: 一行标签就是画面元素，改宽/高/圆角/`transform` 这几个数字就能让按钮变搜索框、变卡片，也能做运镜（缩放、位移）。
- SVG: 用一行字描述一个图形（一行 `circle` 一个圆、一行 `path` 一条曲线），适合图标、logo；靠 `stroke-dasharray/dashoffset` 玩"一笔一笔描出来"。
- Canvas: 给你一块 1920×1080 空白画布，代码一笔一笔画、每帧擦净重画；粒子、像素风、扁平插画这类"成千上万个东西"都靠它。
- WebGL: 着色器，不逐个画，而是写一小段规则给每个像素同时算颜色（1080p=207 万像素）；专做老电视/胶片/霓虹这类质感，通常叠在 canvas 画好的内容上。
- Three.js: 负责 3D 和"摄像机看到的画面"，物体全用三角形拼、可从 Blender 导入，配材质与灯光，能一镜到底跟拍。
- P5.brush: 开源画笔库（11 种笔刷），做彩铅颗粒、炭笔、水彩晕染的手绘感；注意随机种子必须固定，否则画面乱抖。
- 声音: 波形就是一串数字，鼓/贝斯/钢琴可直接算出来，和画面共用同一张时间表，所以卡点比剪辑软件还准。

### 方法论

骨架: 对标（方向）→ 讲法（结构）→ BPM+口播（时间）→ 一镜一物+转场继承（注意力）→ 真素材（可信）→ 自质疑+抽帧数字（验收），每一环都要留一个"能被模型自己读懂"的检查出口；缺任何一环，模型就滑回它那套最俗的默认套路。

#### 1.定方向: 把"审美"翻译成可执行的约束

> 不加约束时模型总用同一套套路，"单看一支很炫，刷多了审美疲劳"，甚至观众已能一眼认出是哪个模型做的。

| 手法         | 具体动作 |
|------------|---|
| 用对标替代形容词   | "高级一点""有设计感"这种话每次理解都不同；换成一部电影片头、一支广告、一个设计流派 |
| 对标要划边界     | 说清"学什么、不学什么": 学节奏/构图/配色思路，别照搬角色/镜头/旋律。例: 火车窗外四季流转+温馨车厢+桌上一杯咖啡+布达佩斯大饭店风格 → 直接落成粉嫩配色+对称构图 |
| 说不清就给样本    | 讲不出参考是什么风格，就把截图、录屏丢给它，让它先分析一遍 |
| 模型给示例+人工选择 | 一段旅程 / 一次前后对比 / 一个东西一路变成另一个；选定一个并说明理由——模型第一个冒出来的想法往往就是最俗的那个 |

#### 2.定节奏: 让时间轴先行，画面后填

> 先定音乐速度，再把镜头拍到拍子上；观众不用数拍子也会觉得卡上了。

| 手法 | 具体动作 | 
|---|---|
| BPM 换算成拍数 | 120BPM = 0.5s/拍，15s 片子 = 30 拍；换镜头、元素砸下来、文字弹出全部落在拍点 |
| 疏密与高潮位置 | 有密的地方也要有松的地方；具体怎么排交给模型，你只需告诉它情绪走向、高潮放在哪 |
| 现成曲子先做节拍分析 | 用别人的曲子也一样，先让它把节拍量出来，画面照节拍走 | 
| 人声优先 | 有口播的片子，人说话时配乐和音效必须让开，否则整支片子都很吵 |

#### 3.定画面: 管住注意力，别让镜头互相打架

> 同一时刻只让观众看一样东西。

| 手法      | 具体动作 | 
|---------|---|
| 转场要精心设计 | 淡出淡入最省事也最没意思；上一镜的圆变成下一镜的太阳，镜头冲进一个按钮、里面就是下一个场景 |
| 镜头本身要动  | 2D 画面一样可以推进、拉远、摇过去 | 
| 变形时不抢戏  | 容器还在变形，文字就别急着进来，等它停稳再出场 | 
| 反 PPT 化 | 讲解片最常见的失败＝口播一句句做成标题卡＋淡入＋背景粒子，看着在动其实在翻 PPT；分镜时先想"这一段要让观众看懂什么变化"，让主角在画面里一直演下去 | 
| 画面自证    | 简单检查: 把字幕藏起来看一遍，光看画面还能看懂才算真的在讲 | 

#### 4.给真东西: 可信度靠素材，不靠模型想象

> 凭想象画出来的界面"一看就是假的"；功能数字、客户名你不给它就会编。

| 手法 | 具体动作 |
|---|---|
| 从代码出发 | 做产品片最好的办法: 直接在项目仓库里打开 Claude，让它先读代码、弄明白有哪些功能，再提炼卖点、排分镜 |
| 喂真实资产 | 一定要给真实 logo、产品截图、网址和品牌色 | 
| 让它自己取证 | 需要出处的数据，让它自己去网上调研，而不是编 |
| 演示要有人味 | 演示功能时加上光标移动、点击和界面反馈，观众更容易看懂怎么用 |

#### 5.看图检查自己: 把"我觉得不行"换成可判定的信号

> 模型能看图，但看不了连续播放的视频，也听不到声音。

| 手法             | 具体动作                                         | 
|----------------|----------------------------------------------|
| 让它(不同厂商的模型)自挑刺 | "你是专业的动效设计师，质疑你自己的策略和计划，如果感觉不像专业设计师做的，就推翻重来" | 
| 口号不够，把片子翻译成它能读的东西     | 光喊"每一帧都要讲究"没用，得给它一个能检查的办法，如: 抽帧拼图 + 运动报告 + 波形/响度数字，替代"看视频、听声音"  | 

#### 6.分段交付: 越长越不能一口气做完

- 先出几张关键帧 → 方向对了再做动画 → 节奏定下来再渲染
- 本质是把上述各层的确认动作摊到不同阶段: 方向在帧上确认、节奏在动画上确认、质量在高清上确认。
